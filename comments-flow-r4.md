# Ghost 评论系统审核同步回拉决策说明 (R4)

> 本文档是可执行的技术决策说明，包含：
> 1. 触发顺序优先级矩阵（同会话 vs 跨会话）
> 2. 每种失败类型的超时值、重试次数、降级动作、提示文案
> 3. 最小改造方案与风险清单

---

## 一、触发顺序优先级矩阵

### 1.1 回拉策略决策树

```
用户操作或系统事件
        │
        ▼
┌─────────────────────────────────────────────────────────────────────┐
│                      是否为同会话操作?                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ┌── Yes (管理员在同一浏览器操作) ────────────────────────────────┐  │
│  │                                                               │  │
│  │  优先级 P0: 本地乐观更新 (API 成功后立即生效)                    │  │
│  │  ├── hideComment: 本地标记 status='hidden', count-1            │  │
│  │  ├── showComment: 重新 read() 拉取完整数据后替换                 │  │
│  │  └── deleteComment: 无回复时 setOrder() 全量刷新                │  │
│  │                                                               │  │
│  │  优先级 P1: API 调用确认                                        │  │
│  │  └── 失败时: 回滚本地状态 + 错误提示                             │  │
│  │                                                               │  │
│  └───────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  ┌── No (管理员在另一浏览器/后台操作) ────────────────────────────┐  │
│  │                                                               │  │
│  │  无 WebSocket/SSE 推送，依赖主动触发                              │  │
│  │                                                               │  │
│  │  优先级 P0: 页面刷新 (F5 / 重新进入页面)                         │  │
│  │  └── initSetup() 完整重新拉取                                   │  │
│  │                                                               │  │
│  │  优先级 P1: 切换排序方式                                        │  │
│  │  ├── setOrder() 触发 page=1 重新拉取                            │  │
│  │  └── firstCommentCreatedAt 重置 (有 order 参数)                 │  │
│  │                                                               │  │
│  │  优先级 P2: 加载更多评论                                        │  │
│  │  ├── loadMoreComments() 追加下一页                             │  │
│  │  ├── firstCommentCreatedAt 锚点仍在使用                        │  │
│  │  └── 只能发现新页数据，已加载页的审核变更无法发现                 │  │
│  │                                                               │  │
│  │  优先级 P3: 用户自身操作触发                                    │  │
│  │  ├── 发表评论: 仅新增评论，不影响旧评论                          │  │
│  │  ├── 点赞/编辑: 乐观更新，不触发全量拉取                         │  │
│  │  └── 打开回复表单: 可能加载更多回复                              │  │
│  │                                                               │  │
│  └───────────────────────────────────────────────────────────────┘  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.3 跨会话审核触发顺序

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         跨会话审核触发顺序                               │
│                                                                         │
│  场景: 管理员 A 在后台审核，访客 B 页面保持打开                            │
│                                                                         │
│  触发事件优先级 (从高到低):                                              │
│                                                                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  P0: 页面刷新 (F5 / 重新进入页面)                                         │
│  ┌───────────────────────────────────────────────────────────────────┐ │
│  │  触发条件: 用户主动刷新或重新导航                                    │ │
│  │  数据范围: 完整重新加载                                            │ │
│  │  回拉动作:                                                         │ │
│  │  ├── initSetup()                                                   │ │
│  │  │   ├── api.init()                                                │ │
│  │  │   └── fetchComments()                                          │ │
│  │  │       ├── api.comments.browse({page:1})                        │ │
│  │  │       │   └── 后端过滤: status NOT IN ('hidden', 'deleted')    │ │
│  │  │       └── api.comments.count()                                 │ │
│  │  │                                                                │ │
│  │  └── (如有 permalink)                                              │ │
│  │      ├── fetchScrollTarget(commentId)                             │ │
│  │      │   └── api.comments.read(commentId)                         │ │
│  │      │       └── 检查 status === 'published'                      │ │
│  │      └── paginateToComment() / loadScrollTarget()                 │ │
│  │                                                                │ │
│  │  firstCommentCreatedAt: 重置为新的第一条评论时间                   │ │
│  │  一致性: 强一致 ✓                                                 │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│                                                                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  P1: 切换排序方式                                                        │
│  ┌───────────────────────────────────────────────────────────────────┐ │
│  │  触发条件: 用户点击 Sort by → Best / Newest / Oldest               │ │
│  │  触发方法: setOrder({order})                                       │ │
│  │                                                                │ │
│  │  actions.ts: setOrder()                                           │ │
│  │  ├── dispatchAction('setCommentsIsLoading', true)                │ │
│  │  │   └── UI 显示半透明加载状态 (opacity: 0.5)                     │ │
│  │  │                                                                │ │
│  │  ├── adminApi.browse / api.comments.browse({page:1, order})      │ │
│  │  │   │                                                            │ │
│  │  │   └── 关键: 有 order 参数时，firstCommentCreatedAt 不生效      │ │
│  │  │       // api.ts:131                                            │ │
│  │  │       if (firstCommentCreatedAt && !order) {  // order 存在时跳过│ │
│  │  │           filter = `created_at:<=${firstCommentCreatedAt}`;   │ │
│  │  │       }                                                        │ │
│  │  │                                                                │ │
│  │  └── 返回: comments, pagination, order                            │ │
│  │                                                                │ │
│  │  数据范围: 第 1 页完整重新拉取                                     │ │
│  │  一致性: 第 1 页强一致，后续页仍有锚点过滤 ✓                      │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│                                                                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  P2: 加载更多评论                                                        │
│  ┌───────────────────────────────────────────────────────────────────┐ │
│  │  触发条件: 用户点击 "Load more ({amount})"                        │ │
│  │  触发方法: loadMoreComments()                                     │ │
│  │                                                                │ │
│  │  actions.ts: loadMoreComments()                                  │ │
│  │  ├── page = state.pagination.page + 1                           │ │
│  │  ├── adminApi.browse / api.comments.browse({page, order})       │ │
│  │  │   │                                                            │ │
│  │  │   └── 关键: 无 order 参数时使用锚点过滤                        │ │
│  │  │       filter = `created_at:<=${firstCommentCreatedAt}`       │ │
│  │  │                                                                │ │
│  │  ├── updatedComments = [...state.comments, ...data.comments]    │ │
│  │  └── dedupedComments = filter(去重)                              │ │
│  │                                                                │ │
│  │  数据范围: 追加下一页，不影响已加载页                              │ │
│  │  一致性: 仅新页数据同步，已加载页可能存在审核延迟 ✗              │ │
│  │                                                                │ │
│  │  问题场景:                                                        │ │
│  │  T0: 加载 [C1, C2, C3, C4, C5] (page 1)                          │ │
│  │  T1: 管理员隐藏 C2 (数据库中 hidden)                              │ │
│  │  T2: 用户点击 "Load more"                                        │ │
│  │  T3: 返回 [C6, C7, C8, C9, C10] (page 2)                        │ │
│  │  T4: 内存中: [C1, C2, C3, C4, C5, C6, ..., C10]                 │ │
│  │      └── C2 仍在列表中！(已加载页不刷新)                          │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│                                                                         │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  P3: 用户自身操作                                                        │
│  ┌───────────────────────────────────────────────────────────────────┐ │
│  │                                                                   │ │
│  │  3.1 发表评论 (addComment)                                        │ │
│  │  ├── api.comments.add()                                          │ │
│  │  ├── comments = [newComment, ...state.comments]                  │ │
│  │  └── 仅新增，不刷新旧评论                                          │ │
│  │                                                                   │ │
│  │  3.2 点赞 (likeComment / unlikeComment)                          │ │
│  │  ├── dispatchAction('updateCommentLikeState', {liked: true})     │ │
│  │  │   └── 乐观更新 (先改本地状态)                                  │ │
│  │  ├── try { api.comments.like() }                                 │ │
│  │  └── catch { 回滚: updateCommentLikeState({liked: false}) }       │ │
│  │      └── 注意: 回滚只针对点赞状态，不刷新整个评论列表              │ │
│  │                                                                   │ │
│  │  3.3 编辑评论 (editComment)                                      │ │
│  │  ├── api.comments.edit()                                         │ │
│  │  └── 本地替换该评论                                               │ │
│  │                                                                   │ │
│  │  3.4 删除评论 (deleteComment)                                    │ │
│  │  ├── 有回复: 本地标记 status='deleted'                           │ │
│  │  └── 无回复: dispatchAction('setOrder', {order})                 │ │
│  │      └── 触发全量刷新 (特殊情况)                                  │ │
│  │                                                                   │ │
│  │  一致性: 仅影响用户操作的那条评论，不触发全量同步 ✗              │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1.4 触发顺序优先级汇总表

| 优先级 | 触发事件 | 数据范围 | 一致性 | firstCommentCreatedAt 重置? |
|--------|---------|---------|--------|---------------------------|
| **P0** | 页面刷新 (F5) | 完整重新加载 | 强一致 ✓ | 是 |
| **P0** | 同会话审核操作 | 本地立即更新 | 强一致 ✓ | 不涉及 |
| **P1** | 切换排序方式 | 第 1 页重新拉取 | 部分一致 ✓ | 是 (order 参数存在) |
| **P2** | 加载更多评论 | 追加下一页 | 部分一致 ✗ | 否 (无 order 时使用锚点) |
| **P3** | 发表评论 | 新增评论 | 仅新评论 | 否 |
| **P3** | 点赞/取消点赞 | 乐观更新该评论 | 仅该评论 | 否 |
| **P3** | 编辑评论 | 替换该评论 | 仅该评论 | 否 |
| **P3** | 删除评论 (无回复) | 触发 setOrder 全量刷新 | 强一致 ✓ | 是 |
| **P3** | 删除评论 (有回复) | 本地标记 deleted | 仅该评论 | 否 |

## 二、失败类型决策矩阵

### 2.1 失败类型分类汇总

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    失败类型分类与决策矩阵                                │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  类 A: 可重试失败 (Retryable)                                            │
│  ┌───────────────────────────────────────────────────────────────────┐ │
│  │  特征: 临时问题，重试可能成功                                        │ │
│  │  策略: 指数退避重试 → 仍失败 → 降级                                 │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│                                                                         │
│  类 B: 不可重试失败 (Non-Retryable)                                     │
│  ┌───────────────────────────────────────────────────────────────────┐ │
│  │  特征: 配置/权限问题，重试也不会成功                                │ │
│  │  策略: 立即降级 + 错误提示                                         │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│                                                                         │
│  类 C: 静默失败 (Silent Failure)                                        │
│  ┌───────────────────────────────────────────────────────────────────┐ │
│  │  特征: message-handler 不返回响应，Promise 永久 pending            │ │
│  │  策略: 超时机制 → 超时后 reject + 清理 handlers                    │ │
│  └───────────────────────────────────────────────────────────────────┘ │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.2 详细决策表

```
┌────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                      失败类型详细决策表                                                 │
├────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                            │
│  ┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐  │
│  │  A. 可重试失败 (Retryable)                                                                          │  │
│  ├────────────────────────────────────────────────────────────────────────────────────────────────────────┤  │
│  │                                                                                                    │  │
│  │  A1. fetch 网络失败 (message-handler.js:67)                                                        │  │
│  │  ├── 触发: 网络抖动、DNS 解析失败、CORS 预检查失败、连接超时                                         │  │
│  │  ├── 检测: fetch() 抛出异常 (TypeError)                                                             │  │
│  │  ├── 分类: 可重试                                                                                   │  │
│  │  │                                                                                                │  │
│  │  ├── 超时值: 无 (fetch 可能有浏览器默认超时)                                                        │  │
│  │  ├── 重试次数: 3 次                                                                                 │  │
│  │  ├── 重试间隔: 指数退避 (1s, 2s, 4s)                                                                │  │
│  │  │                                                                                                │  │
│  │  ├── 降级动作:                                                                                     │  │
│  │  │   ├── 连续失败 3 次: 标记 state.adminAuthDegraded = true                                       │  │
│  │  │   ├── state.adminApi = null (后续操作不再尝试)                                                  │  │
│  │  │   └── UI: 隐藏审核按钮，显示小提示                                                               │  │
│  │  │                                                                                                │  │
│  │  ├── 用户可见提示:                                                                                 │  │
│  │  │   ├── 重试中: 无 (静默重试，用户不应感知)                                                       │  │
│  │  │   ├── 降级后: Toast 提示 "审核功能暂时不可用，稍后刷新页面重试"                                  │  │
│  │  │   └── 现有翻译: 无 (需新增)                                                                     │  │
│  │  │                                                                                                │  │
│  │  └── 恢复机制: 页面刷新时重新尝试初始化                                                             │  │
│  │                                                                                                    │  │
│  ├────────────────────────────────────────────────────────────────────────────────────────────────────────┤  │
│  │                                                                                                    │  │
│  │  A2. HTTP 5xx 服务器错误                                                                          │  │
│  │  ├── 触发: 500 (Internal Server Error), 502 (Bad Gateway),                                         │  │
│  │  │        503 (Service Unavailable), 504 (Gateway Timeout)                                        │  │
│  │  ├── 检测: res.ok === false && res.status >= 500                                                   │  │
│  │  ├── 分类: 可重试 (注意: 500 可能是代码 bug，需谨慎)                                               │  │
│  │  │                                                                                                │  │
│  │  ├── 超时值: 无 (由 fetch 超时决定)                                                                 │  │
│  │  ├── 重试次数: 2 次 (比网络错误少一次，避免加重服务器负担)                                          │  │
│  │  ├── 重试间隔: 指数退避 (2s, 4s)                                                                   │  │
│  │  │                                                                                                │  │
│  │  ├── 降级动作: 同 A1                                                                               │  │
│  │  ├── 用户可见提示: 同 A1                                                                           │  │
│  │  └── 恢复机制: 页面刷新时重新尝试                                                                   │  │
│  │                                                                                                    │  │
│  ├────────────────────────────────────────────────────────────────────────────────────────────────────────┤  │
│  │                                                                                                    │  │
│  │  A3. HTTP 429 Too Many Requests                                                                  │  │
│  │  ├── 触发: 速率限制 (Rate Limiting)                                                                │  │
│  │  ├── 检测: res.status === 429                                                                     │  │
│  │  ├── 分类: 可重试                                                                                   │  │
│  │  │                                                                                                │  │
│  │  ├── 超时值: 读取 Retry-After 响应头 (如果存在)                                                    │  │
│  │  ├── 重试次数: 3 次                                                                                │  │
│  │  ├── 重试间隔: Retry-After 值 或 指数退避 (5s, 10s, 20s)                                           │  │
│  │  │                                                                                                │  │
│  │  ├── 降级动作: 同 A1                                                                               │  │
│  │  ├── 用户可见提示: "操作太频繁，请稍后再试" (需新增翻译)                                            │  │
│  │  └── 恢复机制: Retry-After 过后自动恢复，或页面刷新                                                 │  │
```

### 3.2 P0 改造详细说明

#### 3.2.1 admin-api.ts: 超时机制

```typescript
// 改造前
function callApi(action: string, args?: any): Promise<any> {
    return new Promise((resolve, reject) => {
        function handler(error, result) {
            if (error) return reject(error);
            return resolve(result);
        }
        uid += 1;
        handlers[uid] = handler;
        frame.contentWindow!.postMessage(
            JSON.stringify({uid, action, ...args}),
            adminOrigin
        );
    });
}

// 改造后
const DEFAULT_TIMEOUT = 10000; // 10 秒

function callApi(
    action: string, 
    args?: any, 
    options: {timeout?: number} = {}
): Promise<any> {
    const timeout = options.timeout ?? DEFAULT_TIMEOUT;
    
    return new Promise((resolve, reject) => {
        const requestUid = ++uid;
        
        // 超时定时器
        const timer = setTimeout(() => {
            delete handlers[requestUid];
            reject(new Error(`Admin API call timed out after ${timeout}ms`));
        }, timeout);
        
        handlers[requestUid] = (error, result) => {
            clearTimeout(timer);
            delete handlers[requestUid];
            
            if (error) {
                reject(error);
            } else {
                resolve(result);
            }
        };
        
        try {
            frame.contentWindow!.postMessage(
                JSON.stringify({uid: requestUid, action, ...args}),
                adminOrigin
            );
        } catch (e) {
            clearTimeout(timer);
            delete handlers[requestUid];
            reject(e);
        }
    });
}
```

#### 3.2.2 message-handler.js: 静默失败返回响应

```javascript
// 改造前
if (event.origin !== siteOrigin) {
    console.warn('Ignored message...');
    return;  // 静默忽略
}

// 改造后
if (event.origin !== siteOrigin) {
    console.warn('Ignored message...');
    try {
        event.source.postMessage(JSON.stringify({
            uid: data.uid,  // 注意: data 可能未解析，需要先 try parse
            error: 'Origin mismatch',
            result: null
        }), siteOrigin);
    } catch (e) {
        // 忽略
    }
    return;
}

// 更安全的改造: 先解析，再处理
window.addEventListener('message', async function (event) {
    let data;
    try {
        data = JSON.parse(event.data);
    } catch (err) {
        console.error('Failed to parse message:', err);
        // 无法获取 uid，无法返回有效响应
        // 依赖前端超时机制
        return;
    }
    
    // 此时 data.uid 可用
    if (event.origin !== siteOrigin) {
        console.warn('Origin mismatch');
        respond(new Error('Origin mismatch'), null);
        return;
    }
    
    const handler = actions[data.action];
    if (!handler) {
        respond(new Error(`Unknown action: ${data.action}`), null);
        return;
    }
    
    // ... 其余逻辑
});
```
